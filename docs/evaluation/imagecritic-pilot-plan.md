# ImageCritic: утверждённый первый пилот

Статус: пользователь утвердил план 2026-11-22. **MaSC отложен.**
Старт для Windows: [imagecritic-windows-start.md](imagecritic-windows-start.md).
Prompt для другого OpenCode: [imagecritic-opencode-prompt.md](imagecritic-opencode-prompt.md).
Это исследование, не production интеграция.

## Цель

Проверить вручную: уменьшает ли **один** reference-guided repair конкретное
видимое отклонение диска, сохраняя правильные элементы и окружение.
Без MaSC, VLM-судьи, обучения и автоматической агентной цепочки.

## Порядок

1. Крупно рассмотреть один candidate: №51, предварительно переднее колесо.
   Референс/результат/автомобиль передаются приватно.
   Пользователь подтверждает конкретное отклонение, reference bbox, target bbox
   и то, что должно остаться неизменным. Кандидат может быть отклонён.
2. Диагностика Windows: GPU/VRAM/driver, RAM/disk, Python/CUDA.
3. Отдельное окружение и аудит pinned ImageCritic; лицензии и официальный Kontext.
4. Выбор одного memory profile под фактическую VRAM, без слепого full `.to("cuda")`.
   Совместимость CPU offload с custom pipeline сначала проверить по коду.
5. Подготовить crops без незафиксированного изменения пропорций.
   Показать preprocessing пользователю. Не закрашивать область чёрным в первом опыте.
6. После всех gates один repair одного колеса: фиксированные seed/параметры.
7. Сравнить reference → before → after в одинаковом масштабе и полный автомобиль.
8. Решить: стало лучше / изменений нет / хуже / неразличимо.

## Принятие результата

Успех = **целевое согласованное отклонение уменьшилось, новых существенных ошибок нет**.
Отдельно проверяем:
- правильные ветви, соединения, центр;
- пропорции и finish, свет и материал;
- шину, тормоза, кузов/фон внутри bbox;
- отсутствие видимого шва вставки.

За пределами paste bbox неизменность обеспечена композицией, это не заслуга модели.
Оцениваем именно выход при исходном размере колеса, не только увеличенный crop.
При ухудшении сохраняем before, не принимаем after из-за порядка генерации.
UNCERTAIN не превращаем в PASS. Один успех не доказывает production-надежность.

## Ограничения

- Разметка **границ лицевых частей** принята пользователем. Это не принятие
  всех geometry labels и не утверждение дефекта №51.
- У прежнего Wan A seed20 rear соединения признаны корректными; не чинить их
  по прежнему ошибочному предположению AI/VLM.
- №51 historical result — отдельный кейс; не путать с experimental outputs X5.
- No automatic retries, no seed sweep, no second wheel, no public demos/uploads.
- OOM/ошибка: сохранить статус и остановиться; новый профиль/попытка обсуждаются.
- Никаких production credentials, Supabase/API generations, credits, deploy/merge.
