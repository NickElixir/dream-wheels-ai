# Dream Wheels AI — Release 1 scope

> Обновление 2026-11-05: пользователь отложил интеграцию приложения. Текущий этап — RU/EN дизайн и подготовка статических сборок; этот документ сохраняет контекст будущего интеграционного этапа. Актуальная локальная приёмка: ru-en-sync-acceptance.md.

Зафиксировано 2026-11-05 по плану и уточнениям пользователя. Это состав целевого релиза и критерии приёмки, а не утверждение о готовности production.

## Входит

- RU/EN Landing: Header, Hero, Two Questions, How It Works, Before/After, FAQ, Footer.
- RU/EN Catalog: 5 автомобилей, по 6 дизайнов на автомобиль, 30 Garage-комбинаций; 22 уникальных дизайна и 68 SKU в текущих данных. До 900 px сетка 2×3; desktop — автомобили слева, шесть дисков справа, Garage ниже.
- Существующие финальные изображения и cutouts; раскрываемые характеристики с отдельными плитками исполнений. Без избранного, dropdown SKU и дополнительных подписей под CTA.
- Переходы Hero / вход / BeforeAfter / Catalog / «Моей машины нет в списке» в согласованные существующие сценарии приложения.
- Штатный Auth Gate и восстановление намерения после входа; RU Email OTP, global доступные штатные провайдеры. Telegram на RU не включать в этом треке.
- Create: своё фото автомобиля; выбранный дизайн каталога как источник диска; обычная ручная загрузка без каталога остаётся доступной.
- Явный запуск пользователем, обработка, Result, History, штатные ошибки/повтор. Баланс и существующая оплата проверяются, если нужны для прохождения сценария; новые платёжные возможности не добавляются.
- Независимая проверка совместимости в приложении. Каталог не выдаёт verdict для автомобиля пользователя.
- Сохранение locale/разрешённой атрибуции, серверный учёт новой регистрации по контракту Integration Track.

## Не входит

- Отправка B2B-заявок, Яндекс Формы, HubSpot, Telegram-кнопка для B2B. Существующая демонстрационная форма остаётся с явной подписью до ввода; данных не отправляет, ложного успеха нет.
- Новые экраны выбора SKU, генерации изображений для каталога, массовый fitment audit, новая модель статусов.
- Редизайн приложения и замена действующих vnext UI patterns.
- Автоматический запуск генерации после CTA, входа, обновления страницы или восстановления черновика.
- Изменение Timeweb, Deno gateway, DNS, production domains без отдельной задачи.
- Cross-device перенос черновика, новые CRM/маркетинговые возможности.

## Уточнение compatibility

`unknown` сохраняется. Автор лендинга вручную проверил параметры показанных комбинаций. В приложении это ещё не результат проверки сервисом: пользователь перепроверяет совместимость либо задаёт другую машину/модель. Не присваивать Fitment Engine `verified` по переходу из каталога и не требовать отдельного согласования статусов.

## Дизайн и границы ownership

Landing Track: страницы, сетка, типографика, изображения, локализация и явная B2B-заглушка. Белая CTA каталога «Примерить на моей машине» без иконки сохраняется. Лаймовый Hero — существующее утверждённое оформление, не повод перекрашивать приложение.

Integration Track: destination origins, handoff, manifest, trusted asset adapter, auth capture/restore, регистрационная атрибуция и E2E. Его предложение design-level handoff без SKU отражено в handoff-документе; детали TTL/API остаются контрактом Integration Track, не выдаются за уже реализованные.

WebApp визуально проверять на актуальной main/staging, а не на старом `webapp/` внутри Landing worktree. ## Критерии выпуска

- UI проверен RU/EN на mobile/tablet/desktop; нет clipping, overflow, недоступных CTA и ложных подтверждений.
- Новый и существующий пользователь проходят Catalog → Auth → Create → явный submit → Result → History; выбор/язык не теряются.
- Нет произвольного выбора SKU, подстановки showcase vehicle вместо своего автомобиля или использования Garage image как wheel reference.
- Отмена/ошибки auth, refresh, неизвестный/просроченный ID, повторный переход, ручные правки и двойной submit обработаны.
- Проверены protected assets, ownership и idempotency; реальные действия только в разрешённой среде.
- Тесты Landing и затронутых частей приложения проходят; production cache/locale routing и согласованность версий проверены до выпуска.
- Merge/deploy отдельно разрешены пользователем; есть порядок проверки и отката.

Локальная дизайн-приёмка закрыта в согласованном пользователем объёме; авторизованные экраны — Integration Track. Дизайн-приёмка: `release-1-design-audit.md`. Пакет передачи: `integration-track-release-1-handoff.md`.
