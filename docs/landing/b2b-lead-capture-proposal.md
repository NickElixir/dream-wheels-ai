# B2B Lead Capture — implementation proposal

Статус на 2026-11-05: B2B-интеграция отложена пользователем за пределы первого релиза. Форма остаётся демонстрационной, данные не отправляются; это явно указано перед полями. Ни HubSpot, ни Яндекс Формы не подключаются в этом треке. Решения ниже сохраняются для будущего этапа.
CTA «Обсудить пилот» сохранён. Подтверждение успешной отправки не показывается.

## Решения до реализации

- Получатель: назначить владельца заявок и резервного получателя.
- Хранение: выбрать систему, срок хранения и доступ сотрудников. Уведомление должно ссылаться на сохранённую заявку; ошибка уведомления не должна терять заявку.
- Telegram: подтвердить контакт именно для B2B. `dreamwheelsai` в footer — текущая поддержка, не подтверждённый адрес B2B.
- Антиспам: серверный rate limit, ограничение длины полей, honeypot; необходимость challenge определить по нагрузке. Не выбирать внешнего провайдера автоматически.
- Контактные данные: согласовать текст согласия, оператора, цель, срок хранения и ссылку на политику; отдельный обязательный checkbox без предварительного выбора.

## Предлагаемый сценарий после утверждения

1. Проверить URL (http/https) и телефон, показать ошибки рядом с полем. Сервер повторяет проверку; URL не загружается сервером.
2. Отправить через согласованный endpoint; во время запроса заблокировать повторную отправку, использовать ключ идемпотентности.
3. Сначала надёжно сохранить заявку, затем отправить уведомление с повторными попытками.
4. Только после подтверждения сохранения показать успех. При ошибке сохранить введённые поля и предложить повторить.
5. Необязательная кнопка «Рассказать о магазине в Telegram» / “Tell us about your store on Telegram”. Подсказка: «Пришлите ссылку на магазин и расскажите, где хотите добавить примерку».

Предлагаемый контракт: website, phone, locale, consentVersion, consentAccepted, idempotencyKey. Ответ: сохранённый leadId; отдельные состояния validation error / rate limited / unavailable. Телефон и URL не включать в аналитику, URL перехода в Telegram или клиентские логи.

## Приёмка будущей реализации

Пустые/некорректные поля; согласие; двойной клик; недоступный сервер; повтор после timeout; сохранение без уведомления; доступность ошибок и статусов с клавиатуры; RU/EN. Backend, сервисы и Telegram-переход в текущем треке не реализованы.
