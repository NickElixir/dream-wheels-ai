# Фокус форм — решение владельца от 25.10.2026

Эта политика заменяет прежнее требование фокусировать заголовок редактора после явного открытия формы.

| Переход | Цель |
|---|---|
| Изменить модель / Указать вручную автомобиля | Первое обязательное незаполненное доступное поле; если всё заполнено — марка |
| Ручной редактор диска | Первый незаполненный обязательный параметр; если всё заполнено — первое редактируемое поле |
| Получение характеристик по ссылке | URL |
| Открытие входа / изменение email | Email с прежним значением, без выделения всего текста |
| Успешная отправка OTP | Шестизначный код |
| Поиск параметра | Строка поиска |
| Открытие комплектации | Выбранный либо первый доступный вариант |
| Сохранение | Следующее обязательное поле/вариант; после завершения — заголовок «Итог» |
| Валидация | Первое проблемное доступное поле |
| Общая ошибка запроса | Доступное сообщение ошибки текущего сценария |
| Отмена / Escape | Элемент, открывший текущий редактор/поиск; значения не очищаются |

Если контрол ещё загружается, видимый заголовок блока служит резервной точкой. Pending-намерение действует только в рамках явного открытия, до появления доступного контрола. Другое действие, переход к другому контролу, Escape, отмена, уход и другая примерка прекращают ожидание. Все временные слушатели удаляются после завершения, ошибки или отмены; bootstrap очищает их перед удалением старой формы.

Фоновые ответы, polling, смена языка и redraw сохраняют текущий семантический контрол. Обычная загрузка приложения и восстановление черновика не запускают перенос. Навигация на новый экран, итоговый результат и информационный блок сохраняют заголовки как согласованные цели.

VNext управляет конечной точкой фокуса форм. Legacy не выполняет последующий competing requestAnimationFrame. Auth modal использует одну focus session для email/OTP, с проверкой принадлежности асинхронного ответа текущему открытию.

Прокрутка выполняется только для цели за пределами доступной области; учитываются панели и visualViewport, reduced-motion отключает smooth. Положительные tabindex не используются. Ошибки связаны с полями через aria-describedby; поле и сообщения имеют устойчивые идентификаторы.

## Проверка

`tests/browser-fixtures/form-focus-runtime.html` загружает настоящий app.js, bootstrap и production-компоненты, без подмены refresh/render функций. Подменяются внешние ответы и несвязанные загрузки истории. Панель QA управляет локальными задержками/ошибками; её response/redraw-контролы представляют фоновые события и не считаются новым взаимодействием в приложении. Переход во внешний input остаётся настоящим взаимодействием и отменяет намерение.

`tests/test_form_focus.mjs` проверяет выбор целей, отмену ожидания, очистку слушателей и auth session. Дополнительные регрессии проверяют готовность сохранения при загрузке каталогов и существующие переходы приложения.

Локальные управляемые проверки не заменяют staging E2E, настоящую авторизацию и Telegram WebView. Появление физической клавиатуры на iOS/Android требует отдельной мобильной приёмки; изменение размеров viewport на desktop не доказывает это поведение.
