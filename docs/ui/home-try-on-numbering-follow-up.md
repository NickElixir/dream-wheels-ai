## Утверждённая подпись главного экрана

- Если есть подтверждённая пользователем марка/модель автомобиля, показывать её.
- Иначе показывать `Примерка #12` / `Try-on #12`, где 12 — стабильный порядковый номер примерки внутри аккаунта.
- Бренд, модель, артикул и характеристики диска не использовать как fallback названия.
- «Примерка автомобиля» не является выбранным fallback.

Изменение подписей на History/Result требует явного определения scope отдельного PR; согласование в этом документе относится к главному экрану. Формат вторичной строки даты/времени остаётся отдельным решением.

## Текущее поведение и разница

`src/jobs_api.py` создаёт job_id через `uuid.uuid4()`.
`webapp/app.js: humanRenderTitle` использует подтверждённый vehicle, затем данные диска, затем первые шесть символов job_id.
Эти символы не являются порядковым номером и не отражают последовательность создания.
`#previous-2` в локальном preview был демонстрационным текстом, а не серверным номером.

## Требования к отдельной реализации

1. Назначать и хранить номер на сервере в рамках аккаунта; UUID сохраняется техническим идентификатором.
2. Номер не должен зависеть от позиции в загруженном списке, пагинации, сортировки или фильтров.
3. Одновременное создание и повтор идемпотентного запроса не должны создавать дублирующиеся номера или перенумеровывать существующую примерку.
4. Подготовить миграцию для существующих примерок по порядку создания с детерминированным разрешением одинаковых timestamps.
5. Определить и зафиксировать политику failed/cancelled/deleted jobs и объединения аккаунтов до реализации; не делать скрытых продуктовых предположений. Принятые номера не должны меняться при обычном просмотре истории.
6. Передать номер через необходимые create/history/detail API и использовать его в Home view model без глобальной несогласованной замены shared title helper.
7. Если номера нет, не представлять UUID или индекс страницы как порядковый номер. Политику переходного fallback согласовать в PR.
