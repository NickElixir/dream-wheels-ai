# Phase 08E — Wan runtime integration

Phase 08E connects the existing render worker to the provider-neutral
`GenerationProvider` boundary. The single active provider is Alibaba Cloud
Model Studio Wan 2.7 with `WAN_MODEL=wan2.7-image`.

## Active runtime

```text
job
  -> reserve credit (API, once)
  -> Redis job_queue
  -> worker: processing
  -> GenerationRequest(vehicle, rim reference, P0_API_SPIKE)
  -> WanImageProvider: submit -> bounded poll -> download/validate
  -> durable result asset
  -> job completed
  -> finalize credit (once)
```

The worker sends the vehicle first and rim reference second. It derives an
explicit output size from the vehicle image dimensions; it does not send
`2K`, does not enable bbox, and always requests `n=1` and `watermark=false`.

Wan transport failures use the normalized provider error taxonomy. Submission
transport uncertainty is not retried and never falls back to Reve. Internal
diagnostics are logged only in redacted form; user-visible job errors remain
provider-neutral.

## Durable metadata

The existing `jobs` columns persist `generation_provider`,
`provider_request_id`, `generation_latency_ms` and `generation_cost` (nullable
where provider pricing is not configured). The default estimate is USD 0.03
per successful `wan2.7-image` result and is controlled by
`WAN_ESTIMATED_COST_USD`; it is not an Alibaba billing statement. Migration
`0029` adds nullable `provider_task_id`. The selected model is logged in the worker and analytics;
there is no `generation_model` column in the inspected schema.

Generated bytes are downloaded before the temporary Alibaba URL can expire and
then stored through the existing `assets_service` result path. The temporary
URL is never stored as the canonical result URL.

## Startup and rollout

No Alibaba configuration is read during API import or startup. If the worker
receives a job while `WAN_API_KEY`, `WAN_WORKSPACE_ID` or another Wan setting is
invalid, that job deterministically follows the existing failed/refunded path
with `provider_config_error`; the worker does not silently use Reve.

Migration `0029` must be applied before deploying the 08E code. Live staging
validation, production cutover and the final
`Rendering → Fitment → Rendering → Fitment` flow are deferred to 08F/08G.
